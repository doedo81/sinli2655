# 자리배치·과제관리에 학생 이름 표시 — 설계

작성일: 2026-07-29

## 문제

자리배치와 과제 관리 화면에 학생 번호만 나온다. 선생님이 번호와 이름을 매칭하지 못해
누가 과제를 안 냈는지 바로 알기 어렵다.

원인은 화면 코드가 아니라 **데이터**다. `settings/dashboardDefaults/roster`에 저장된
명단이 번호와 성별뿐이고 이름이 비어 있다.

```
1	여
2	여
3	남
```

자리배치(`nsParseRoster`, 2764행)와 성장 탭(`rpgParseRosterStr`, 4584행)은 이미 이름을
파싱하며, 이름이 없을 때만 `번호 + "번"`으로 폴백한다. 즉 **이 두 화면은 명단에 이름만
들어가면 코드 수정 없이 이름이 나온다.**

과제 관리(`renderHomeworkList`, 4133행)만 명단을 아예 보지 않고 `1..total` 숫자를
찍고 있어 코드 수정이 필요하다.

## 제약: 명단은 무인증 공개 경로다

2026-07-29에 게시한 Firebase 보안 규칙에서 `rooms/$cid/settings/dashboardDefaults`는
`".read": true`다. 학생 핸드폰 로그인(`rpgStudentInit`, 5602행)이 로그인 없이 명단을
읽어야 하기 때문이다.

따라서 기존 `roster`에 이름을 넣으면 학생 실명 전체가 인터넷에 공개된다. 같은 날 막은
개인정보 노출을 되돌리는 셈이므로 허용하지 않는다.

Firebase 규칙은 위에서 아래로 상속되며 상위의 `.read: true`를 하위에서 되돌릴 수 없다.
그래서 "`roster`만 비공개로" 같은 방식은 불가능하다.

## 결정: 이름을 별도 노드로 분리

| 노드 | 내용 | 접근 |
|---|---|---|
| `rooms/$cid/settings/dashboardDefaults/roster` | 번호 + 성별 (현행 유지) | 무인증 공개 |
| `rooms/$cid/settings/rosterNames` | 번호 + 이름 + 성별 (신규) | **로그인 필요** |

`rosterNames`는 `dashboardDefaults` 바깥이므로 상위 `rooms/$cid`의 `.read`(로그인 필요)를
그대로 물려받는다. **보안 규칙을 고칠 필요가 없다.**

검토했으나 채택하지 않은 대안:

- **기존 `roster`를 잠그고 학생용 공개 노드를 신설** — `dashboardDefaults` 공개를 끊는 순간
  다른 선생님 소유 학급 11개의 학생 로그인이 전부 깨진다. 그 방들에 마이그레이션 쓰기를 할
  권한도 없다.
- **`roster`에 이름을 넣고 규칙으로 그것만 비공개** — Firebase 규칙 상속 구조상 불가능.

## 데이터 흐름

### 입력 (선생님 UI는 안 바뀜)

명단 입력 칸(`set-student-roster`, `rpg-roster-input`)에 기존 형식대로 넣는다.
이 형식은 이미 placeholder(1172행)에 안내돼 있다.

```
1 김민수 남
2 이서연 여
3 박준호 남
```

저장할 때 코드가 둘로 쪼갠다.

```
rosterNames ← "1 김민수 남\n2 이서연 여\n3 박준호 남"   (원본 그대로, 비공개)
roster      ← "1 남\n2 여\n3 남"                      (이름 제거, 공개)
```

이름 제거는 공백 토큰 단위로 판단한다. `tok === '남' || tok === '여'`인 토큰만 성별로
인정한다. `text.includes('남')` 방식은 `김남수` 같은 이름을 성별로 오인하므로 쓰지 않는다.
(기존 `parseStudentRoster` 2536행에 이 문제가 있으나 이번 범위 밖이다.)

### 읽기

| 화면 | 소스 | 결과 |
|---|---|---|
| 선생님 PC·태블릿 (로그인됨) | `rosterNames` → 없으면 `roster` | 이름 표시 |
| 학생 핸드폰 (무인증) | `roster` (현행 그대로) | 번호만 |

읽은 값을 기존 전역 변수 `globalStudentRosterStr`에 넣는다. 이 변수를 쓰는 하위 화면
(자리배치·성장·모둠뽑기)은 **손대지 않는다.**

## 수정 지점

### 1. 쓰기

- `saveSettingsData()` (4268행) — `settingsRef.set(data)`로 `roster`를 통째로 쓴다.
  `data.roster`에 이름 제거본을 넣고, 원본은 `rosterNames`에 따로 쓴다.
- `rpgWriteRoster()` (4605~4606행) — `settingsRef.update({roster: txt})`.
  동일하게 분리해서 쓴다.
- 두 곳 모두 저장 직후 `globalStudentRosterStr`에는 **이름 포함 원본**을 넣는다
  (4278행, 4605행). 저장 직후 화면에서 이름이 사라지면 안 된다.

### 2. 읽기

- `enterRoom()` (1807행) — `settingsRef.once`와 나란히 `rosterNames`도 읽어,
  값이 있으면 그것을 `globalStudentRosterStr`에 넣는다.
  `parseStudentRoster()` 등 파싱 호출보다 **먼저** 완료돼야 하므로 두 읽기를
  `Promise.all`로 묶는다.
- `openSettingsModal()` (4237행) — 설정 모달의 명단 textarea를 `rosterNames` 기준으로 채운다.
  없으면 기존대로 `d.roster`.
- `rpgStudentInit()` (5602행) — **수정하지 않는다.** 학생 폰은 계속 `roster`만 읽는다.

### 3. 과제 관리 버튼 (renderHomeworkList, 4133행)

번호 위, 이름 아래 2단 구성. 셀 폭(55px)과 한 줄 개수는 그대로 둔다.

```
┌──────┐┌──────┐┌──────┐
│  1   ││  2   ││  3   │
│김민수││이서연││박준호│
└──────┘└──────┘└──────┘
```

- 번호 18px (현행 유지), 이름 12px
- 이름이 없는 학생은 이름 줄을 생략한다 → 지금과 동일한 모양
- 명단 조회는 `rpgParseRoster()`로 한 번만 만들어 `id → name` 맵으로 쓴다
  (학생 수만큼 `find()`를 반복하지 않는다)
- 이름은 반드시 `escapeHtml()`을 거친다

### 4. 제출 통계 (renderStats, 4220행)

같은 과제관리 탭의 "제출 통계" 뷰도 `1번 학생`으로만 나온다. 여기도 이름을 붙인다.

- `1번 학생` → `1번 김민수`
- 이름이 없으면 기존대로 `1번 학생`
- 3번에서 만든 `id → name` 맵을 함께 쓴다

## 마이그레이션

없다. 순수 추가 방식이다.

- 기존 학급은 `rosterNames`가 없으므로 `roster`로 폴백 → **지금과 완전히 동일하게 동작**
- 선생님이 명단에 이름을 넣고 저장하는 순간 해당 반에 `rosterNames`가 생긴다
- 다른 선생님 소유 학급에 아무 영향 없다
- 보안 규칙 변경 없음

## 비목표 (이번에 하지 않음)

- 학생 핸드폰에 이름 표시
- 아침 칠판 당번 표시에 이름 추가 (`4번, 5번` 유지)
- `parseStudentRoster`의 성별 오판정 버그 수정 (`김남수`를 남자로 오인)
- 이름 입력을 돕는 별도 UI (기존 textarea 그대로 사용)

## 검증

1. 명단에 이름을 넣고 저장한 뒤, 무인증으로 두 경로를 찔러본다.
   - `settings/dashboardDefaults/roster.json` → 200, **이름 없어야 함**
   - `settings/rosterNames.json` → **401이어야 함**
2. 자리배치 탭에 이름이 뜨는지 (코드 수정 없이 동작해야 함)
3. 과제 관리 버튼에 번호+이름이 뜨고, 제출/면제/미제출 3상태 토글이 그대로 되는지
   (제출 통계 뷰도 `1번 김민수`로 나오는지)
4. 이름을 일부 학생만 넣었을 때 나머지는 번호만 나오는지
5. 학생 핸드폰 로그인이 여전히 되는지 (무인증 `roster` 읽기 유지 확인)
6. 이름에 `<img src=x onerror=...>`를 넣어도 실행되지 않는지
